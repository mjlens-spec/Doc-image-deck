# 阶段 4 · 可编辑还原

每页的产出是一张去掉文字的底图 + 覆盖在上面的可编辑文本框。照片、图标、色块、装饰、截图留在底图里；原稿 PPTX 里的独立对象（Logo、页码、贴图）原样保留。适用于本流程生成的图文版，也适用于别人做的整页图片 PPTX 或 PDF。

## 一次跑完首轮

在项目目录下运行：

```
$S/deck editable 04_可编辑 03_合成/<图文版>.pptx 04_可编辑/<name>_可编辑版_<suffix>.pptx \
    --outline 00_白板稿/outline.json --ref 03_合成/<图文版>.pdf
```

外来稿件没有白板稿时，把 `--outline` 换成 `--draft <prompt 目录或文案 md …>`，或不给文案库。`--ref` 是用于比对的原稿 PDF，没有时与抽出的页面图比对。

依次执行：抽页（`extract_pages.py`）→ 建文案库（`corpus.py`）→ 分层（`layers.py`，2 进程；4K 页面每页 15–40 秒）→ 装配（`build_pptx.py`）→ PowerPoint 导出 PDF 并逐页比对（`verify.py`）→ 校对表（`proof_sheet.py`）→ 全稿对照（`qa_sheet.py`）。输出都在工作目录的 `03_QA/`。

## 审阅与返修

1. **版面审阅**：看 `03_QA/全稿对照_*.jpg`。截图、海报、图表、表情包、产品卡片、竖排文字卡片里的文字应留在底图，用 `$S/deck review <工作目录> <输出.jpg> p05 p09` 生成带坐标网格的叠加图（绿框 = 宋体，蓝框 = 黑体，红框 = 留在底图），把区域写进 `config.json` 的 `pages.<pid>.exclude_boxes`。排除区要完整包住 OCR 行框才生效；行框通常比墨迹大 10–30 像素，坐标以 `02_分层/<pid>/ocr.json` 或 review 图上的框为准，四边各留 15 像素余量。
2. **文字校对**：看 `03_QA/校对表_*.png`（含非常用字的行、三路识别不一致的行）。错字写进 `replace`（全稿）或 `pages.<pid>.replace`（单页），键以 `re:` 开头按正则处理。
3. **切分**：白板稿 `kpis` 块里带中文前缀或单位的大数字（「约 250 条」「310 万元」），按白板稿自动切成前缀、数字、单位三段（见下文「大数字与单位」），不需要手工处理。其他大字与小字混排、自动切不开的行，在 `pages.<pid>.split_points` 写 `[x, y]`，x 取两段之间的空白处。每行只取第一个落在行框内的切分点，两段都至少有 2 个字才会切开。外来稿件没有白板稿，KPI 组切不开时放进排除区留在底图。
4. 重跑涉及的页：`$S/deck layers <工作目录> p05 p09`，然后 `$S/deck build <工作目录> <输出.pptx>` 和 `$S/deck verify <工作目录> <输出.pptx> <输出.pdf> --ref <原稿.pdf>`。
5. 局部放大核对：`$S/deck zoom <工作目录> <输出.pdf> <页序> <pid> x0 y0 x1 y1 <out.png>`。
6. 交付统计：`$S/deck report <工作目录> <输出.pptx>`；页面措辞与旧稿的差异：`$S/deck draftdiff <工作目录>`（影响语义的差异在交付检查里单列）。

原图本身的错字（生图错字）：本流程生成的稿件按白板稿纠正；外来稿件保持原样并写进交付检查，品牌名、产品名、人名的错字按正确写法改并注明。

## 已验证的规则

- **基线**：PowerPoint（Mac 16.113）在固定行距下，基线距文本框顶端的距离只取决于行距，与字号、与这两套思源字体无关，而且呈 1pt 级台阶，不是线性关系。必须用 `calibration.json` 的查找表（行距取 0.25pt 的整数倍）。文本框一律零边距、顶端对齐、不自动换行（`wrap="none"`）。Windows 版 PowerPoint 由 `deck setup` 单独标定，查找表按实测生成；「只取决于行距」这一规律在 Windows 上尚未验证。
- **可变字体**：思源宋体可变字体的 Light / Regular / Medium / SemiBold / Bold / Black 在 PowerPoint 中渲染正确；ExtraLight 实例映射错误，不用。
- **OCR**：Vision 返回的逐字框是把整行等分，不是真实字形位置，不能用来判断字距和空格。Vision 常漏读"的"，也会把相近字读错（千→干、的→钓 / 前）。做法是整页识别 + 单行裁切 1.0 倍、1.6 倍再识别，三路逐字投票，只接受替换和补字、不接受删字，标点以整页识别为准。
- **两种文案库**：本流程生成的稿件用 `--outline` 按页建库，白板稿文字视为准确文字，匹配上就直接替换识别结果（含数字）。外来稿件只能用旧文案（prompt、逐页稿），这时文案库只作校正参考：原始文案往往是早期版本，页面上的措辞可能已经改过（本次 p05「做」、p31「可靠」都与旧稿不同）。文案库只允许修改三路识别有分歧的字，补字只限「的、了、之、地、得」；其他差异保留页面原文，记入 `layers.json` 的 `draft_diffs`，交付时列出。
- **图标与装饰**：行首图标常被读成「Q」「A」「苗」「0」「)」，行尾花饰读成「J」「8」「+」「（Ccs」。两路裁切识别都没有的行首 / 行尾短符号一律删除，对应墨迹留在底图。月相、星芒等纯装饰行（有效字符不超过两个）不转换。
- **宋体 / 黑体判断**：用形态学开运算分别取出横笔和竖笔，沿笔画横截面对墨迹浓度积分（对模糊不敏感）。横竖比：生图宋体约 0.25–0.5，黑体约 0.8–1.1。字重按竖笔积分匹配。同一页里字号、颜色相同的行视为同一样式，先按字数加权投票定字体，再取总误差最小的字重。
- **空格**：中文与数字 / 英文之间是否有空格、空格多宽，按整行渲染后与原图的逐列墨迹分布比对决定；空格单独设字距。
- **大小字混排**：标签和说明、大号数字和正文常被 Vision 识别成同一行。按墨迹逐列测字高，空隙两侧字高相差 30% 以上、且空隙明显大于正常字距时切成两段，切在哪个字由左半段单独 OCR 决定（裁切不能越过切口，否则会把右半段的字补回来；切口后的标点归左段）。同一行里相邻的两个识别框也互不越界。间距过小切不开的（如「70 万不只买曝光」），在 `pages.<pid>.split_points` 里写切分点坐标 `[x, y]`。
- **编号徽章与分隔线**：圆圈编号（①…）和实心圆徽章里的数字不转为文字，徽章留在底图；行两端的细竖线（标签 | 内容）不算字形。
- **照片上的字**：用文字外圈（半个行高）灰度 5×5 局部标准差的中位数判断，阈值 6。色块、横幅边缘只占少数像素，不影响中位数；本次正常文字 99% 在 3 以下，压在照片、截图上的在 5 以上。
- **下划弧线**：标题下方的装饰弧线常与文字墨迹相连，会把字号估大 30% 以上，按行覆盖率从上下缘修剪（见 04b_还原技术细节.md 第 3 节第 5 条）。
- **拉丁字母与汉字**：小写拉丁字母比汉字矮，按字高切分大小字混排时，切口落在拉丁字母与汉字交界处的不切（「Agent 负责…」是一行，不是大小字混排）。
- **窄字形标题**：生图的粗黑体标题常比思源黑体窄，只靠负字距对齐宽度会让相邻字相叠。字距最紧到字号的 −6%；还宽时，行高不低于页高 4.5% 的标题行先向右侧空白延伸（最多原宽度的 10%，不越过右侧相邻文字和页面 96% 处），仍不够再缩小字号。只在字号要缩小 5% 以上时延伸；正文行不延伸，免得同一段里字号不一。
- **大数字与单位**：用 `--outline` 建文案库时，`kpis` 块的数值另存一份。识别行的数字与某个数值相同时，在这一行及左右各延伸一段的范围内取墨迹：先去掉细长的分隔线、横线和小斑点，再按墨迹列分出字形；最高的一组是数字，左右两侧底边对齐、明显更矮的字形是前缀和单位，前缀和单位的宽度要与字数相符。三段各自按白板稿文字拟合字号，单字前缀「约」、单字单位「条」也保留。切不开（前缀、单位与数字一样高）时按一行处理。测试中 4 组全部自动切开。
- **超大数字**：高于页高 18%、以数字为主的行留在底图：这么大的字形去字后，LaMa 会在周围留下灰色光晕。标题等以文字为主的大字照常转换。
- **按白板稿匹配**：一行同时能完整匹配两条白板稿文字时（如栏目标题「单一对象」也出现在标题「一个单一对象，每人一个 Agent」里），选整条都匹配上的那一条，不从较长的句子里带出相邻标点。4–5 个字的短行少识别一个字（Vision 常漏读「的」）时，也按白板稿补回。
- **大面积去字的兜底**：大字去字的区域很大时，LaMa 偶尔会在中间填出一块灰色。区域外圈是单一底色时，填充结果里偏离底色较远（色差 25 以上）的像素改为底色，细网格、纸纹等浅图案保留。
- **大字的背景色**：粗笔画的大字会占满中值滤波的窗口，背景色被估成文字颜色，文字取色变成底色。行框外一圈是单一颜色、而框内估出的背景有 15% 以上偏离这个颜色时，改用外圈颜色作背景。
- **按方向限定字体族**：新建工作目录时，`deck editable` 读项目 `02_生图/prompts/direction.json` 的 `type_classes`：只用黑体、圆体时只拟合思源黑体，只用宋体时只拟合思源宋体，写进 `config.json` 的 `families`；混用或含楷体、行楷时两族都拟合。
- **纯数字 / 英文行**：笔画太少，横竖比判断不可靠，字体族沿用本页汉字最多的那一族，只在族内选字重。
- **留在底图的内容**：行首项目符号和图标（保持原样的金色圆点等）、字高不足 18px（按 3840 宽折算，页面更窄时按比例缩小）的小字、照片上的字（背景杂乱度超阈值）、含日文假名 / 韩文的乱码行、纯装饰行、`exclude_boxes` 内的全部文字。
- **原稿对象**：直接在原 PPTX 上替换满幅图片的图像数据，文本框插在底图正上方，Logo、页码、贴图保持原位置和层级；原稿中未安装的字体名（如 Source Han Sans SC）换成同设计的已安装字体。

## 已知限制

- 文字按真实字体重排，生图字形的笔画细节、压印阴影、烫金质感不再保留；渐变金字用上下两色的线性渐变近似。
- 竖排文字、弧形文字、极小字、艺术字标题不会被识别，保留在底图里（可见但不可编辑）。
- 底图为 JPEG（质量 92），与输入页面同尺寸；整套 PPTX 体积约为每页 1–2 MB。
- 字体只写本机已装的思源宋体 / 思源黑体；对方电脑缺字体时会被替换，需要对外编辑时提醒对方安装（均为 SIL OFL 免费字体）。
