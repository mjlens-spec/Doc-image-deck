# 技术细节与参数

首次验证：一份 74 页的珠宝品牌整合营销提案（3840×2160 生图稿，宋体 / 黑体混排，纸纹、烫金、深绿底），2026-09-25。

## 1. 文件与目录

```
<工作目录>/
  manifest.json        extract_pages.py 生成：每页原图、需保留的原稿对象 id
  corpus.json          corpus.py 生成：文案库片段
  config.json          人工维护：排除区、替换表、切分点、阈值

  01_原图/pNN.png
  02_分层/pNN/         layers.json、plate.jpg（去字底图）、debug.jpg（叠加图）、preview.jpg（本地预览）、ocr.json
  03_QA/               verify.py 的逐页对照图、diff.json、交付检查 md
```

## 2. config.json

完整示例见 `config_示例.json`。

| 键 | 默认 | 说明 |
|---|---|---|
| `families` | `["serif","sans"]` | 参与判断的字体族；整套只用一种字体时限定为一个 |
| `min_ink_height_px` | 18 | 字高低于此值的文字留在底图；按 3840 宽计，页面更窄时按宽度比例缩小 |
| `max_background_std` | 6 | 文字外圈灰度 5×5 局部标准差的中位数超过此值，视为照片 / 截图上的字 |
| `bullets_in_plate` | true | 行首项目符号、图标保留在底图 |
| `ocr_vote` | true | 裁切重识别投票 |
| `plate_quality` | 92 | 底图 JPEG 质量 |
| `font_remap` | Source Han → Noto | 原稿对象里未安装字体的替换表 |
| `pages.<pid>.exclude_boxes` | — | 原图像素坐标 `[x0,y0,x1,y1]`；行框 60% 以上落在框内即保留在底图 |
| `pages.<pid>.families` | — | 单页限定字体族 |
| `pages.<pid>.split_points` | — | 人工切分点 `[[x, y], …]`（原图像素），落在某行框内时从 x 处切成两段 |
| `replace` / `pages.<pid>.replace` | — | 校对后的替换表；键以 `re:` 开头按正则处理 |
| `proof_allow` | — | 校对表中不必再标出的非常用字（人名、专有名词用字） |
| `split_by_height` | true | 是否自动按字高切分混排行 |
| `corpus_authoritative` | false | 为 true 时文案库视为准确文字（`corpus.py --outline` 生成的文案库自带此标记） |

## 3. 每行文字的处理顺序

1. Vision 整页识别 → 按字间大空隙切段（表格列、分栏标题）→ 按字高变化切段（大小字混排）。Vision 的逐字框不精确，只用来切段和定行框，不用于判断字距。
2. 相邻行框上下重叠时以重叠区中线截断（大标题的行框常比字高出 60% 以上）。
3. 过滤：单个符号、乱码（含 2 个以上日文假名 / 韩文；只有 1 个时视为装饰并删掉该字）、装饰（有效字符 ≤2 且不足三成，或全是月相类括号字母）、排除区、行首项目符号 / 圆圈编号 / 图标、两端竖线。
4. 裁切 1.0 倍、1.6 倍重识别，三路投票（圆圈编号不参与替换）；删去两路裁切都没有的行首 / 行尾短符号（句号后的「一」「C」、行尾花饰；数字单位后的「+」保留）；再用文案库纠正（只改有分歧的字，补字只限虚词；数字不改；OCR 把破折号读成"一"时按文案恢复）；最后套用替换表。
5. 墨迹：局部中值背景（核 ≈0.9 行高）求色差；行框内非墨迹像素颜色均匀时（色块、横幅）改用单一背景色。取包含行中心的一条墨迹带；行首小墨块（项目符号）、颜色或高度与正文不一致的行首墨块（月牙、图标）、实心圆徽章、两端细竖线剔除；行首为「一」等扁平字时不剔除。以汉字为主的行没有下伸部，墨迹带上下缘连续超过 15% 行高、且只覆盖不到 35% 行宽的行视为下划弧线等装饰，修剪掉；宽而扁、贴在带边缘的连通块同样剔除。
6. 字体族与字重：横竖笔画积分比定字体族（先用各族 Regular 判，差距 0.25 以内的族都进入第二轮），再在族内按竖笔积分选字重。
7. 字号由墨迹高度反推，字距由墨迹宽度反推；空格位置与宽度按逐列墨迹分布比对。
8. 颜色逐字取中位数，相近的合并为同一段；上下三分之一颜色差 >38 且都属于文字时用上下渐变。
9. 页内按字号 ±10%、颜色 ±50 聚类为同一样式，统一字体族、字重和字号。
10. 纵向相邻、同样式、行距稳定、左 / 中 / 右对齐一致的行合并为一个文本框，用换行分隔。

## 4. PowerPoint 装配

- 在原 PPTX 上修改：满幅图片的 `r:embed` 指向新底图，旧图关系删除；文本框插在底图元素之后。
- 文本框：`wrap="none"`、四边距 0、`anchor="t"`、`lnSpc/spcPts` = 行距（取 0.25pt 整数倍），框顶 = 首行基线 − 查找表偏移。
- 字距：`rPr@spc`（百分之一磅），PowerPoint 在每个字符后都加；空格单独成段，带自己的字距。
- 字体：`latin`、`ea`、`cs` 三处写同一个字体名；Bold 用 `b=1`，其他字重用独立字体名（如 `Noto Serif SC SemiBold`）。
- 导出：`osascript` 调 PowerPoint 另存为 PDF；文件先复制到 `~/Library/Containers/com.microsoft.Powerpoint/Data/tmp/deckrender/`。直接打开桌面上新建目录里的文件会被沙盒拦截（报 -9074 或卡在授权框）。

## 5. 性能与资源

- 4K 页面单页 20–40 秒，其中 LaMa 修补占一半以上。
- LaMa 在 MPS 上必须限制显存：`PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.4`、`PYTORCH_MPS_LOW_WATERMARK_RATIO=0.25`，修补块单边不超过 1600px（超出分片、重叠 160px），每块后 `torch.mps.empty_cache()`。16 GB 内存最多开 2 个进程；不限制时单进程可占 8–10 GB，3 进程会导致系统换页停滞。

## 6. 本次实测数据

- 字重在 PowerPoint 中的 CJK 笔画密度（20pt）：宋体 Light 0.097 / Regular 0.111 / Medium 0.123 / SemiBold 0.139 / Bold 0.160 / Black 0.188；黑体 Light 0.106 / DemiLight 0.146 / Regular 0.162 / Medium 0.203 / Bold 0.248 / Black 0.292。
- FreeType 排版宽度与 PowerPoint 实际宽度之比 0.995–1.002。
- 基线：两种字号的查表结果平均相差 0.009pt；相对 0.752×行距的线性近似，误差在 −0.92 到 +0.75pt 之间。
- 字重闭环检查（PowerPoint 渲染 vs 原图的竖笔积分比）：浅底中位数 1.002，深底 1.09。
