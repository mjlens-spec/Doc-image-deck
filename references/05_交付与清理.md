# 阶段 5 · 交付与清理

## 交付物

放在项目根目录：

| 文件 | 来源 |
|---|---|
| `<name>_白板稿_<suffix>.pptx` | `00_白板稿/` |
| `<name>_图文版_<suffix>.pptx` / `.pdf` | `03_合成/` |
| `<name>_可编辑版_<suffix>.pptx` / `.pdf` | `04_可编辑/` |
| `05_QA/交付检查_<suffix>.md` | 本阶段编写 |

## 交付检查模板

```markdown
# 交付检查 · <项目名>

检查日期：<YYYY-MM-DD>

## 一、交付物
| 文件 | 说明 |（页数、尺寸、体积；PDF 由 PowerPoint 导出）

## 二、制作方式
白板稿（含标点整理，用户确认日期）→ 设计方向（列出 3 个方向、各自来源是用户参考还是自行设计，以及用户选定的方向）→ 逐页生图（Codex 内置 image_gen，单页 1672 × 941，放大 2 倍）→ 合成（Logo、页码为独立对象）→ 可编辑还原。

## 三、校验结果
| 项目 | 结果 |
页数与比例；PPTX 完整性（unzip -t）；生图文字核对（textcheck 结果、重生成的页及原因）；
可编辑版：文字可编辑行数与缺失数、与图文版的逐页平均色差（均值与最高三页）、使用字体。

## 四、文字处理说明
按白板稿纠正的生图错字；保留页面原文的差异（如有）。

## 五、留在底图、不可编辑的内容
类型、处数、所在页。

## 六、已知差异
字形质感、字重近似、大小字混排等。
```

写作遵循宿主的写作规范：陈述事实和数字，不写评价性形容词。

## 清理

`$S/deck cleanup <项目> --dry-run` 先看清单，再 `$S/deck cleanup <项目>`。

| 保留 | 删除（默认） | `--deep` 另删 |
|---|---|---|
| outline.json、白板稿、去 AI 味与标点整理记录 | 各级 `tmp/` | 每页选定的生图原稿 |
| direction.json、参考图（`ref/`）与样张、方向对比图、方向说明、参考候选清单与对照图 | 未选用的生图版本 | 方向样张 |
| 提示词、selected.json、textcheck.json、联系表 | `03_合成/pNN.png`（已嵌入图文版） | |
| 每页选定的生图原稿 | `04_可编辑/01_原图`，`02_分层/*/` 的底图、调试图、预览图（已嵌入可编辑版） | |
| `04_可编辑/config.json`（人工审阅结果）、`manifest.json`、`layers.json` | `04_可编辑/03_QA/cmp_*.jpg` | |
| 项目根目录的全部 PPTX、PDF 与交付检查 | 阶段目录里与根目录同名同大小的交付文件副本；PowerPoint 容器里的中转文件 | |

清理后：改字直接在可编辑版 PPTX 里改；要重新生成可编辑版（例如补排除区），用 `deck editable` 从图文版重跑，`config.json` 里的审阅结果会沿用；要重新合成图文版，用保留的选定生图原稿跑 `deck compose`。
