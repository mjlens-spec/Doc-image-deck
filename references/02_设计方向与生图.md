# 阶段 2 · 设计方向与生图

## 1. 品牌调研与 Logo

设计方向要建立在客户的品牌上。没看品牌 VI 就定方向，三个方向可能都用了和品牌色冲突的主色，反白 Logo 也可能落在浅底上。所以写方向之前先做 10–15 分钟的快速调研，`deck directions` 在调研完成前拒绝通过。

### 材料

- 客户提供：品牌手册或 VI 规范、Logo 文件（彩色版、反白版、单色版）、往期提案和物料、官网或电商页面截图。在确认点 1 向用户索取，放进 `01_设计方向/品牌材料/`，或写进 `project.json` 的 `brand_materials`。
- 联网检索：品牌官网（关于我们、产品页）、公开的品牌手册、电商旗舰店首页与详情页、官方社交账号。Claude Code 用 WebSearch / WebFetch；Codex 要以 `codex --search` 启动会话才有联网检索。只用检索结果提炼规范，不下载、不复用对方的图片和文案。

### 步骤

1. `deck brand <项目> init`：生成 `01_设计方向/品牌调研.md` 模板，列出找到的材料和已配置的 Logo。
2. 逐个阅读材料。截图和图片直接看；PDF、PPTX 先导出：`deck refs <项目> --export <文件> --pages 1,3,5 --to 01_设计方向/品牌材料/导出`，挑色彩页、Logo 页、版式页和典型物料页。
3. 联网检索补足材料里没有的内容，记下网址和检索日期。
4. 填写六节，写事实，不写评价：

| 节 | 写什么 |
|---|---|
| 一、资料来源 | 每份材料的文件名、页码和看到的内容；网址与检索日期 |
| 二、品牌色 | 主色、辅助色的色值（#RRGGBB）和出处；哪一个是强调色 |
| 三、Logo | 有哪些版本，各适合浅底还是深底，文件路径；是否要做联合 Logo |
| 四、字体与版式 | 标准字与常用字体；物料的网格、留白、标题位置 |
| 五、视觉风格与禁忌 | 摄影或插画风格、质感、关键词；品牌手册明确禁止的用法 |
| 六、对三个方向的约束 | 三个方向都要遵守的底线，如品牌色必须出现、Logo 周围留白、禁用色 |

   查不到的写「不适用：<原因>」，不要猜色值。
5. `deck brand <项目> check` 通过后再写方向。检查项：六节齐全，品牌色至少有一个色值，资料来源至少有一个文件路径或网址。

### Logo

只用客户提供或官方发布的 Logo 文件，不让生图模型画，也不自己重画。

`deck logo <项目> <Logo>[::<反白版>] [<Logo2>[::<反白版>]] [--corner bl] [--height 0.32]`：

| 情况 | 处理 |
|---|---|
| 同时有浅底版和深底版 | 用 `a.png::a_white.png` 成对给出 |
| 只有反白版（白字） | 白色笔画改为 `--ink` 指定的灰色（默认 #656565），生成浅底用版本；彩色部分保留 |
| 只有深色版 | 深色笔画改为白色，生成深底用版本 |
| 彩色版 | 深浅底共用，深底上看不清时向用户要反白版 |
| 不透明的白底或黑底图片 | 去掉底色 |
| 多个 Logo | 按面积平衡视觉分量，左右排列，中间一个细「×」，生成联合 Logo |

输出 `00_Logo/<名称>_浅底用_<suffix>.png`、`_深底用_` 和 `预览.png`，并写入 `project.json` 的 `logos`（相对路径）。自动生成的版本要看一眼 `预览.png` 再用。Logo 尺寸决定提示词里预留角落的大小，所以要在生成提示词之前完成。

## 2. 视觉参考

### 查找与询问

`deck refs <项目> [其他目录 ...]` 在三类位置查找：项目目录、项目的上级目录、`project.json` 里 `source` 原文档所在的目录（深度 3 层），外加命令行给出的目录。收录图片（PNG、JPG、WebP、HEIC、TIFF，短边不小于 480 像素、不小于 40 KB）、PDF、PPTX、Keynote；跳过 Logo、图标、头像、二维码、本项目的阶段目录和交付文件。路径里含「参考、风格、视觉、情绪板、品牌手册、主视觉、提案、海报、moodboard、reference、style、KV、VI、brand」等词的排在前面；同一目录下图片超过 6 张时只列最相关的 3 张。结果写在 `01_设计方向/参考候选/`：`候选清单.md`、`候选对照.jpg`（R01、R02 … 编号的缩略图）、`candidates.json`。

候选在确认点 1 与白板稿一起给用户。问法要点：列出候选编号和文件名，附对照图；请用户指定要用的编号，或另外提供参考文件；说明一个参考对应一个方向，其余方向自行设计。用户说没有，就三个方向都自行设计。

### 导出

`deck refs <项目> --export <R03|文件路径> [--pages 1,4] --to 01_设计方向/A/ref`：

| 类型 | 处理 |
|---|---|
| PNG / JPG | 原样复制 |
| HEIC / WebP / TIFF | 用 `sips` 转为 PNG |
| PDF | 按 `--pages` 渲染为长边 1600 像素的 PNG（默认第 1 页） |
| PPTX | 先用 PowerPoint 导出 PDF，再按页渲染 |
| Keynote | 请用户在 Keynote 中导出 PDF 后再导出 |

每个方向的参考图不超过 2 张，挑最能代表风格的页（封面、一页典型内容页）。

## 3. direction.json

每个方向一个文件，放在 `01_设计方向/<A|B|C>/direction.json`。`light` / `dark` 是整段风格描述，原样进入每页提示词，用英文写（生图模型对英文风格描述更稳定），中文文字只出现在页面文案里。

```json
{
  "id": "A",
  "name": "科技杂志 · 冷白与电光蓝",
  "summary": "给用户看的一句话：像科技杂志的专题版面，冷白底、深海军蓝标题、电光蓝强调，照片为光纤与数据中心",
  "source": "original",
  "refs": [],
  "brand_fit": "品牌蓝 #008ED3 作为唯一强调色；深色封面与封底用反白 Logo；照片调色偏冷，与品牌官网一致",
  "imagery_mode": "photo",
  "dims": {
    "typeface": "粗黑体标题 + 黑体正文 + 等宽小标签",
    "palette": "冷白底、海军蓝与电光蓝",
    "layout": "杂志式非对称，12 栏网格",
    "imagery": "光纤、机房等数字科技实景",
    "texture": "平面印刷，冷调电影感照片"
  },
  "light": "Style/medium: premium technology-magazine editorial slide, crisp and restrained, high-end corporate-proposal quality\nBackground: cool paper white #F2F5F8, flat, no texture behind text\nColor palette: ink navy #0B1B2B for titles and body; muted slate #5B6B79 for secondary text; brand blue #008ED3 for labels, numbers, rules and key highlights\nTypography: bold modern Chinese sans-serif (黑体) titles; regular Chinese sans-serif body; small uppercase monospace labels with wide letter-spacing; clear hierarchy\nLayout grid: margins 6% left and right; title block from 8% of the height; strict left alignment on a 12-column grid; hairline rules; generous whitespace; asymmetric magazine composition",
  "dark": "Style/medium: premium technology-magazine editorial slide, cinematic and restrained\nBackground: deep navy-black #06121D\nColor palette: white titles; light grey-blue #9FB3C5 body; brand blue #008ED3 and cyan #4FD3F5 accents only\nTypography: very bold Chinese sans-serif titles; regular Chinese sans-serif body\nLayout grid: margins 6%; strict left alignment; hairline rules; generous negative space",
  "imagery": "Imagery: photoreal, cinematic, digital-technology subjects (optical fibre, data centres, circuitry, light trails, telecom towers); unified cool grading; every slide uses a different subject",
  "avoid": "newspapers, handshakes, meeting rooms, generic stock-business imagery, cartoon icons, emoji, heavy drop shadows, glossy 3D clip-art",
  "tone": {"cover": "dark", "section": "dark", "content": "light", "closing": "dark"}
}
```

| 字段 | 说明 |
|---|---|
| `source` | `reference`：按用户提供的参考建立；`original`：自行设计 |
| `brand_fit` | 这个方向怎样用品牌：品牌色放在哪里、Logo 落在深底还是浅底、如何呼应品牌的视觉风格；要满足 `品牌调研.md` 第六节的约束。`deck directions` 检查必填，并写进方向说明的「品牌呼应」一行 |
| `refs` | 参考图路径（相对本文件所在目录或绝对路径），`source` 为 `reference` 时必填。`deck prompts` 把它转成绝对路径写进提示词目录的 `direction.json`，`deck gen` 自动附上 |
| `imagery_mode` | 配图方式，三选不同：`photo` 写实摄影、`still_life` 产品静物、`illustration` 插画、`graphic` 纯图形（无照片）、`material` 材质肌理、`3d` 三维渲染、`typographic` 纯文字排版。提示词会要求把每页的配图建议按这种方式画 |
| `dims` | 五项维度的中文短描述：`typeface` 字体、`palette` 配色、`layout` 版式语法、`imagery` 配图、`texture` 质感。`deck directions` 用它检查差异并生成对比表 |
| `summary` | 给用户看的一句话，写清这个方向看起来像什么 |

### 三个方向要完全不同

`deck directions <项目>` 的检查：品牌调研已完成；正好 3 个方向，每个方向都写了 `brand_fit`；必填字段齐全；按参考建立的方向参考图存在；五项 `dims` 两两都不相同；`imagery_mode` 各不相同；浅色页或深色页底色相同时给出提示。检查通过后写 `01_设计方向/方向说明.md`，作为确认点 2 给用户的对比表。

| 维度 | 可选项举例 |
|---|---|
| 字体 | 宋体标题 + 黑体正文 / 全黑体、粗细对比强 / 宋体为主的书卷气 / 手写或书法点缀 |
| 配色 | 品牌主色 + 中性色；深浅底比例；是否用金属色、渐变；高饱和撞色 / 低饱和同色系 |
| 版式语法 | 杂志非对称 / 瑞士网格 / 居中仪式感 / 卡片模块 / 满版图上叠字 |
| 配图 | 写实摄影 / 产品静物 / 插画 / 纯图形 / 材质肌理 / 三维渲染 / 纯文字 |
| 质感 | 平面印刷 / 纸艺压印烫金 / 光影电影感 / 颗粒胶片 / 玻璃与光泽 |

三个方向都要贴合客户行业和内容语气，并遵守品牌调研第六节的约束。品牌色可以在三个方向里都出现（例如都作强调色），差异放在底色、字体、版式、配图和质感上。按参考建立的方向尽量贴近参考；自行设计的两个方向与参考方向、与彼此都要拉开。只在配色上换一换、配图都是同一类题材的三个方向不算不同。

### 按参考建立方向

1. 用 `deck refs --export` 导出参考页，打开看图。
2. 提炼：底色和主要颜色（写出色值）、标题与正文字体类型和字重、版式语法（网格、对齐、留白、分区方式）、配图处理（题材、光线、调色）、质感（纸纹、颗粒、光泽）。写进 `light` / `dark` / `imagery` / `dims`。
3. 参考只提供风格。参考里的文字、Logo、品牌名、人物肖像不写进方向，也不要求模型复现；参考是其他品牌的物料时尤其注意。
4. 参考只有浅色页时，`dark` 按参考的配色推导，样张出来后再核对。

## 4. 提示词结构（build_prompts.py 自动拼装）

1. 规格：一张完整的 16:9 横版幻灯片、第 n / N 页、印刷品质。
2. 方向风格：`light` 或 `dark` 段落 + `imagery` + `imagery_mode` 对应的配图方式（配图建议写「无照片」时以配图建议为准）。
3. 全稿统一与变化：风格系统（底色、配色、字体字重、标题位置与字号、边距、线条与图标、配图调色）每页一致；构图和图示类型随本页内容变化，不退回「标题 + 卡片」的默认版式。
4. 本页视觉规划（`visual`，见 `01_白板稿.md`「逐页视觉规划」）：这一页要说清什么、信息结构、画法、视觉焦点、构图骨架，以及前后两页用的骨架和结构，要求本页与之明显不同。
5. 本页版面与配图：页面角色、`layout_hint`、`image_hint` 与 `motif`；有信息结构的页另加图示规则：箭头、分组、大小和颜色差异都要对应文字里的关系，标签紧贴它说明的图形，不画没有含义的箭头、图标和假图表，代表数字的形状按数值比例画；图上只写引号里的文字，不加自行计算的数字和标签。页面有脚注且底部有预留角落时，要求脚注放在预留角落上方。
6. 逐字文案：`- 角色: "文字"` 按阅读顺序列出；正文块带 `visual` 时，这块文字归在「Group n — draw as: …」下面。
7. 文字规则：只画引号里的文字（分组说明和其他指令都不是上屏文字），简体中文逐字准确，数字、单位、标点照写，原文没有句号的地方不加句号，不加英文装饰词。
8. 预留角落：按 `project.json` 的 Logo 和页码位置计算的角落留空。
9. 禁画：任何 Logo（含 `brands` 中的品牌）、页码、水印、二维码、伪造手机截图 / App 界面、乱码，以及方向里的 `avoid`。

使用风格参考图时（`--ref-light` / `--ref-dark` 的样张，以及按参考建立的方向的 `refs`，每次合计最多 3 张），`gen_batch.py` 在提示词前加一段说明：附图只提供风格；附图是同一套稿的其他页，不照搬其文字、内容、构图、图示类型和配图题材，本页要与它不同。模型容易照搬参考图的构图，这段说明和第 4 项的前后页对照一起防止全稿雷同。

## 5. 运行

| 事项 | 数值 |
|---|---|
| 单张耗时 | 约 1–2 分钟（Codex 0.155，2026-09 实测：样张 55–70 秒，4 页并发全量 77 秒） |
| 并发 | 4 路稳定；更高并发容易超时 |
| 输出 | 1672 × 941 PNG；阶段 3 放大 2 倍到 3344 × 1882 |
| 失败处理 | 每张自动重试 1 次；仍失败的页在输出末尾列出，退出码 1 |
| 额度 | 走 ChatGPT 套餐的生图额度；`imagegen.py` 会先确认 Codex 用 ChatGPT 账号登录，否则停止，避免产生 API 费用 |

样张：3 个方向 × 2 页 = 6 张，约 3 分钟；三个方向可以分别后台运行 `deck gen`。附参考图时单张约 1.5–2 分钟。

## 6. 质检

`deck textcheck` 对每页做 OCR：

- `MISS`：有文案没找到（缺字、错字、整条漏掉）→ 重生成。
- `CORNER`：Logo 或页码的预留角落里出现了文字 → 重生成；多页都压角时改 `project.json` 的角落。
- `PUNCT`：某行结尾出现句号，而白板稿里这句没有句号（模型自行加的）→ 看图确认后重生成。
- `NEAR`：文案基本找到，个别字 OCR 读法不同，多为识别误差 → 看图确认。

重生成：`deck gen 02_生图/prompts --out 02_生图/raw --pages p05,p11 --ref-light … --ref-dark …`，新版本自动编号并被选中。两轮后仍不过的页，先改写版面建议（如把表格改成分栏）；需要删减字数、拆分长句时，属于改动已确认的文字，先告诉用户，确认后改 `outline.json`、重跑 `deck whiteboard` 和 `deck approve`，再 `deck prompts --pages p05` 并生成。

人工看联系表时检查：

1. 对照 `00_白板稿/视觉规划.md`：每页的图示类型和构图骨架按规划落地；相邻两页构图雷同、图示画错关系（箭头方向、回流路径、比例）的页，重写该页 `visual.form` 后重生成。
2. 配图题材全稿不重复。
3. 同级标题字号、页眉样式、边距一致；个别页风格漂移时加参考图重生成。
4. 没有乱码、没有多出来的英文装饰字、没有自己画的 Logo 或页码。
5. 数字和专有名词逐一核对。

## 7. 已知问题

- 只给文字和一句版面建议时，模型多数页会画成「标题 + 三张卡片」，附同一张样张作参考时更明显。逐页视觉规划（`visual`）和参考图说明就是为此加的；联系表阶段仍要逐页对照视觉规划看一遍。
- 模型会把画法说明里提到的词（「内容端」「每周」）和自行算出的百分比画成标签，`textcheck` 查不出多出来的文字，要在联系表里看。
- 模型不严格遵守底部留白，靠 `CORNER` 检查兜底；脚注最容易落进左下角。
- 表格超过 5 列或单元格字多时错字明显增加，优先改成分栏或拆页。
- 繁体字偶发（運、與、黃），`textcheck` 会报 `NEAR` 或 `MISS`；可编辑还原阶段会按白板稿纠正。
- 真实人物肖像：只有用户提供参考图并确认可用时才画；不确定时用产品、静物或抽象画面代替。

## 8. 在 Codex 里单页返修

Codex 会话里可以直接调用内置 `image_gen` 工具：把 `02_生图/prompts/pNN.txt` 的内容作为提示词原样传入，生成后把图片复制为 `02_生图/raw/pNN_v<下一个编号>.png`，再更新 `selected.json`。批量生成仍用 `deck gen`，它能并发并自动记录。
