# 环境与安装

支持 macOS（Apple 芯片或 Intel）和 Windows 10 22H2 / Windows 11（2024 年及以后的版本）。两个平台都需要 Microsoft PowerPoint 和 Codex CLI。

## 安装 skill

macOS：

```bash
git clone https://github.com/mjlens-spec/Doc-image-deck.git
python3 Doc-image-deck/scripts/install.py
```

Windows（PowerShell）：

```powershell
git clone https://github.com/mjlens-spec/Doc-image-deck.git
py -3 Doc-image-deck\scripts\install.py
```

`install.py` 把 skill 本体（`SKILL.md`、`LICENSE`、`agents/`、`references/`、`scripts/`）复制到 `~/.agents/skills/doc-image-deck/`，在 `~/.claude/skills/` 与 `~/.codex/skills/` 各建一个链接（macOS 用符号链接，Windows 用目录联接，不需要管理员权限），两个宿主共用一份文件；然后执行 `setup.py` 安装运行环境。修改仓库里的文件后重跑 `install.py --no-setup` 同步。

## 命令入口

| 平台 | 入口 | 说明 |
|---|---|---|
| macOS | `scripts/deck` | sh 启动器，调用 `deck.py` |
| Windows | `scripts\deck.cmd` | 批处理启动器，调用 `deck.py`；PowerShell 中写 `& "$S\deck.cmd" help` |

两个启动器都优先使用运行环境里的 Python，并以 UTF-8 模式运行全部脚本（Windows 控制台默认代码页不是 UTF-8）。`deck check`、`deck setup`、`deck imagegen` 用任意 Python 3.10+ 就能运行。

## 运行环境（deck setup）

运行环境放在 `$DOC_IMAGE_DECK_HOME`，默认 macOS 为 `~/.local/share/doc-image-deck/`，Windows 为 `%LOCALAPPDATA%\doc-image-deck\`，与 skill 文件分开，两个宿主共用。

| 项目 | macOS | Windows | 用途 |
|---|---|---|---|
| Python 3.10+ | `brew install python` | `winget install Python.Python.3.12` | 运行全部脚本 |
| 虚拟环境 `venv/` | numpy、scipy、opencv-python-headless、pillow、python-pptx、lxml、torch、fonttools、pypdfium2、onnxruntime 等；simple-lama-inpainting 与 rapidocr 用 `--no-deps` 安装 | 同左，另加 pywin32、pillow-heif | |
| LaMa 权重 | `~/.cache/torch/hub/checkpoints/big-lama.pt`，196 MB，断点续传 | 同左（`%USERPROFILE%\.cache\…`） | 去字修补 |
| 文字识别 | Apple Vision：`bin/ocrbox`，由 `ocrbox.swift` 用 `swiftc` 编译（需 `xcode-select --install`） | RapidOCR：PaddleOCR PP-OCRv6 模型（随 rapidocr 安装，Apache-2.0） | 识别生图文字 |
| PDF 渲染 | poppler（`brew install poppler`）；没有时用 pypdfium2 | pypdfium2 | 抽页、比对、标定 |
| 字体 | `~/Library/Fonts/`：`NotoSerifSC-wght.ttf`（可变字体）与 `NotoSansCJKsc-*.otf` | 文件放在 `<运行环境>\fonts\` 供拟合；思源宋体按 6 个字重生成静态字体（名称与 Mac 上的字体名一致），连同思源黑体为当前用户安装 | 可编辑版字体 |
| 微软雅黑 | 不自动下载，缺失时白板稿在本机显示为替换字体 | 系统自带 | 白板稿 |
| humanizer-zh | 各 skills 目录都没有时 `git clone` 到 `~/.agents/skills/humanizer-zh` 并链接给两个宿主 | 同左 | 去 AI 味 |
| Codex CLI | `npm i -g @openai/codex` 或 `brew install codex`，再 `codex login`（ChatGPT 账号） | `winget install OpenJS.NodeJS.LTS`，再 `npm i -g @openai/codex`、`codex login` | 生图 |
| PowerPoint | Microsoft PowerPoint for Mac，AppleScript 驱动 | Microsoft PowerPoint（Microsoft 365 / 2021 及以后），COM 驱动 | 导出 PDF、比对、标定 |
| 标定 | `calibration.json`：打开 PowerPoint 约 1 分钟 | 同左，按 Windows 版 PowerPoint 单独标定 | 可编辑版文本框定位 |

`deck check` 只检查不修改；`deck setup --no-fonts` 不下载字体；`--no-calib` 跳过标定。PowerPoint 或字体版本变化后删除 `calibration.json` 重跑 `deck setup`。

Windows 上有 NVIDIA 显卡时，可以先设置环境变量 `DOC_IMAGE_DECK_TORCH_INDEX=https://download.pytorch.org/whl/cu124` 再运行 `deck setup`，安装 CUDA 版 torch，LaMa 自动用显卡。已经装过 CPU 版时，先删除 `venv` 目录。

## 资源占用

- 可编辑还原阶段默认 2 个并行进程（`DOC_IMAGE_DECK_WORKERS` 可改），每个峰值约 1.5 GB。macOS 上 LaMa 用 Apple GPU，已限制显存水位，16 GB 内存最多 2 个进程；Windows 没有 NVIDIA 显卡时 LaMa 用 CPU，每页耗时更长。
- 生图 4 路并发，受 ChatGPT 套餐的生图额度限制；74 页的稿件约 40 分钟。

## 测试

- `python3 tests/run_tests.py`：不依赖运行环境的检查，CI 在 Linux 与 Windows 上运行。
- `<运行环境的 python> tests/pipeline_smoke.py`：用一张合成页面走完抽页、识别、拟合、LaMa、装配（不含 PowerPoint 与 Codex）。CI 在 Windows 上完整安装运行环境后运行。在 Mac 上加 `DOC_IMAGE_DECK_OCR=rapid DOC_IMAGE_DECK_PDF=pdfium` 可以走 Windows 用的识别与渲染路径。
